# v1.1 M6: 取得失敗の分類と再試行

作業ブランチは `feat/v1.1-m6-m8`。この変更の対象は M6 であり、M7 の検索・分割と M8 の評価拡張は含まない。

## 最初の診断

指定された `.venv/bin/browsr open https://go.dev/doc/devel/release` を最初に実行したところ、既存キャッシュから正常に本文を返した。過去の評価ログには同 URL の `blocked` があったが、旧サービス層は例外の `detail` をログに保存していなかった。そのため、過去の記録だけから原因を復元することはできなかった。

分類を変更する前に `detail` の記録を追加し、キャッシュの保存先を分けて再実行した。

```sh
BROWSR_CACHE__PATH=/tmp/browsr-m6-diagnosis-20260923.sqlite \
  .venv/bin/browsr open https://go.dev/doc/devel/release
```

`~/.local/state/browsr/calls.jsonl` の 2026-09-23T08:41:19.865909+00:00 の記録は次のとおりだった。

```json
{"outcome":"blocked","cache":false,"detail":"RuntimeError: Set changed size during iteration"}
```

この再現での原因は `BrowserPool._check_requested`。要求 URL の `set` を走査しながら `await guard.host_allowed(...)` を呼ぶ間に、ブラウザのイベントが同じ集合に URL を追加していた。サイトの CAPTCHA ではなく内部例外であり、旧サービス層が想定外の例外を `blocked` に分類していたため、サイトに拒否されたように見えていた。

修正後、別の空のキャッシュを使った同 URL の実行は成功した。ログは `outcome: "ok"`、`cache: false`、`via: "browser"`、`detail: ""`（2026-09-23T10:11:09.218875+00:00）だった。PyPI の `https://pypi.org/project/httpx/` も実 API から取得でき、`via: "adapter"` と本文・バージョン・リリース履歴を確認した。

## 変更内容

- ブラウザの要求 URL 検査で可変集合を直接走査しないようにし、非同期処理中の追加に対する回帰テストを追加する。
- CAPTCHA・アクセス拒否は `blocked`、通信・ブラウザ・内部の失敗は `fetch_failed` に分類する。タイムアウト、404/410、禁止アドレスは別の分類を維持する。例外の詳細は公開応答に含めず、ログの `detail` に最大300文字で記録する。
- タイトルと、短いページの本文先頭1,500文字で Fastly / Cloudflare などのチャレンジを判定する。通常の短い記事を長さだけで拒否しない。
- サイト別取得、auto モードの HTTP、主ブラウザ、設定されたフォールバックの順に試す。再試行するエラーは `blocked` と `fetch_failed` に限定し、すべて失敗したら最後のエラーを返す。
- 主ブラウザが `blocked` になったホストは既定で3,600秒記憶する。HTTP フォールバックは有効、追加の Camoufox は利用可能な場合に遅延起動する。`calls.jsonl` の `via` に成功または失敗した取得方法を記録する。
- PyPI のプロジェクト URL は JSON API からメタデータ、リリース日、リンク、説明を読み取る。バージョン指定、yanked、共有 HTTP クライアントのアクセス制御・サイズ制限を扱う。

## 検証範囲

DESIGN §21 の M6 に該当する追加項目は、`detect` の fixture、`PageLoader._load` の順序・記憶期限・再試行しないエラー・`via`、`PyPIAdapter` の JSON fixture で検証する。ブラウザの可変集合エラー、HTTP の失敗分類、ログの詳細・長さ制限についても回帰テストを追加する。

REST と実 Firefox を通すローカル統合テストでは、ブラウザのチャレンジから HTTP に切り替わること、同じホストで主ブラウザをスキップすること、キャッシュ利用の記録、チャレンジ本文をキャッシュしないこと、404で再試行しないことを確認する。

M7 の `rank.best_part`・部分選択・自己リンクの追加テストと、M8 の評価テストはそれぞれのマイルストーンで追加する。
